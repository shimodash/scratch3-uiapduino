scratch3-uiapduino のキーボード対応の実装仕様。マウス（段階 1）の完了時点で書いたもの。

| | 状態 |
|---|---|
| マウスのブロック | **全ブロック実機確認済み** |

## 1. 設計方針：押しっぱなしを作れるブロックを置かない

マウスで採った方針をキーボードにも適用します。

**`キーを押したままにする` / `キーを離す` のブロックは用意しません。**

理由はマウスと同じです。利用者が「離す」を書き忘れれば、Shift や Ctrl が押されたまま
残ります。そこで USB を抜かれると、操作していたアプリに修飾キーが押されたままの状態が
取り残されます。**そもそも押しっぱなしを作れないようにすれば、この問題の分類ごと消えます。**

Shift や Ctrl の押しっぱなしは、マウスのボタンより厄介です。ボタンなら
「どこかを 1 回クリックすれば消える」のに対し、修飾キーは気づきにくく、
その後のすべてのキー入力が化けます。

代わりに、**すべてのブロックを 1 コマンドで完結する形**にします。
修飾キーは `KEY_SHORTCUT`（`0x35`）の中で押して離すところまでを
デバイス側が一括で行うので、コマンドの外に漏れません。

デバイス側の `KEY_PRESS`（`0x32`）/ `KEY_RELEASE`（`0x33`）/ `KEY_RELEASE_ALL`（`0x34`）は
**残しますが、ブロックとしては露出しません。** `PANIC` の経路と将来の拡張のためです。

> マウス側では `ドラッグしながら〔 〕` という囲みブロックを用意して、
> 押しっぱなしをブロックの内側に閉じ込めました。**キーボードには同等のものを
> 用意しません。** 「Shift を押しながら複数の操作をする」需要はマウスのドラッグほど
> 強くなく、危険性は高いためです。必要になったら同じ仕組み（`BlockType.LOOP`）で
> 後から足せます。

## 2. 追加するブロック

| ブロック（日本語） | コマンド |
|---|---|
| `[Hello UIAPduino] とタイプする` | `KEY_TEXT` (`0x30`) を分割して連投 |
| `[Enter▼] キーを押して離す` | `KEY_WRITE` (`0x31`) |
| `[Ctrl▼] を押しながら [c] キーを押す` | `KEY_SHORTCUT` (`0x35`) |

既存の `キーとマウスをすべて離す`（`PANIC`）はそのまま。

### 文言（`message` 定数に追加）

```js
keyType: {
    ja: '[TEXT] とタイプする',
    'ja-Hira': '[TEXT] とタイプする',
    en: 'type [TEXT]'
},
keyWrite: {
    ja: '[KEY] キーを押して離す',
    'ja-Hira': '[KEY] キーをおしてはなす',
    en: 'press and release [KEY]'
},
keyShortcut: {
    ja: '[MOD] を押しながら [KEY] キーを押す',
    'ja-Hira': '[MOD] をおしながら [KEY] キーをおす',
    en: 'press [MOD] + [KEY]'
}
```

メニュー項目の文言（`Enter` `Backspace` などのキー名、`Ctrl` `Shift` などの修飾キー名）は
**そのまま英字で構いません。** キートップの刻印と一致する方が分かりやすいためです。

## 3. ワイヤフォーマット

### `KEY_TEXT` (`0x30`) — 文字列をタイプする

| バイト | 内容 |
|---|---|
| `[0]` | `0x30` |
| `[1]` | フラグ（`0x80` = 続きあり）|
| `[2..31]` | ASCII、0 終端 |

#### ⚠ 1 回に送れるのは **29 文字**

Feature Report は 32 バイトですが、**デバイス側が `buf[31] = 0` で終端を強制します。**

```c
case CMD_KEY_TEXT:
  buf[31] = 0;                              // ← ここで 30 文字目が潰れる
  Keyboard.print((const char *)&buf[2]);
```

したがって文字を置けるのは `[2..30]` の **29 バイト**です。30 文字入れると
最後の 1 文字が消えます。**気づきにくい壊れ方なので注意してください。**

#### ⚠ フラグは現状デバイス側が見ていない

上のコードのとおり、`[1]` のフラグは読まれていません。
**単に 29 文字ずつに切って順に送れば、そのまま順番にタイプされます。**
`uiapduinoProcessor` のキューが直列化するので、順序は保証されます。

フラグは将来のために予約されているだけです。`0x80` を立てても害はありませんが、
**「フラグを立てないと繋がらない」わけではありません。**

#### ⚠ ASCII のみ。日本語は打てない

`Keyboard.print()` は `const char *` を取り、HID のキーコードに変換して送ります。
**IME は通りません。** 日本語の文字列を渡しても意味のある入力になりません。

Scratch 側で ASCII 以外の文字が含まれていたら、
**黙って捨てず、開発者コンソールに警告を出してください。** 無言で化けるのが最悪です。

#### ⚠ US 配列前提

HID はキーコードを送るだけなので、**PC 側のキーボード配列で解釈が変わります。**
日本語配列（JIS）の PC では `@ : _ [ ] \ ^` などがずれます。

英数字とスペースは配列によらず正しく入ります。**まずはそこまでを確実に動かし、
記号の配列対応は後回しでよい**と考えます。対応する場合は、ブロックに
`キーボードの配列 [US▼/JIS▼]` を持たせ、Scratch 側（JS）で記号のキーコードを
差し替える表を持つことになります。デバイス側は変更不要です。

### `KEY_WRITE` (`0x31`) — キーを押して離す

| バイト | 内容 |
|---|---|
| `[0]` | `0x31` |
| `[1]` | キーコード |

デバイス側は `Keyboard.write()` を呼びます。`write()` は内部で
press → 10ms → release → 50ms を行います。**USB のポーリング（10ms）に確実に
拾わせるための待ちなので、短くしないでください。**

### `KEY_SHORTCUT` (`0x35`) — 修飾キーと組み合わせて押す

| バイト | 内容 |
|---|---|
| `[0]` | `0x35` |
| `[1]` | 修飾キーのビット |
| `[2]` | 一緒に押すキーのキーコード |

修飾キーのビット（`.ino` の実装と一致していること）:

| ビット | キー |
|---|---|
| `0x01` | Ctrl |
| `0x02` | Shift |
| `0x04` | Alt |
| `0x08` | Windows (GUI) |

デバイス側の動作:

```
修飾キーを press → 20ms → キーを press → 20ms → releaseAll()
```

**押して離すところまで 1 コマンドで完結します。** 修飾キーがコマンドの外に漏れません。

## 4. キーコード表

`arduino_core_ch32` の `Keyboard.h` の定数。`KEY_WRITE` のメニュー値に使います。

| キー | 値 | キー | 値 |
|---|---|---|---|
| Enter | `0xB0` | Home | `0xD2` |
| Esc | `0xB1` | PageUp | `0xD3` |
| Backspace | `0xB2` | Delete | `0xD4` |
| Tab | `0xB3` | End | `0xD5` |
| Insert | `0xD1` | PageDown | `0xD6` |
| → | `0xD7` | ← | `0xD8` |
| ↓ | `0xD9` | ↑ | `0xDA` |
| CapsLock | `0xC1` | PrintScreen | `0xCE` |
| F1–F12 | `0xC2`–`0xCD` | NumLock | `0xDB` |

修飾キー単体（`0x80` LeftCtrl 〜 `0x87` RightGUI）は**メニューに出しません。**
単体で押しても意味がなく、押しっぱなしを作る道具にしかならないためです。

### `KEY_SHORTCUT` の第 2 引数

`[2]` はそのまま `Keyboard.press()` に渡されるので、**ASCII 文字（`'c'` = `0x63`）でも
上の `KEY_*` 定数でも通ります。**

ただしブロックとしては **ASCII 1 文字のテキスト入力**（`Ctrl + c` など）だけを
提供することを勧めます。`Alt + F4` や `Alt + Tab` を組めるようにすると、
子どもが試して PC の状態を壊す余地が増えます。必要になってから足せます。

Scratch 側では、入力文字列の**先頭 1 文字だけ**を取り、ASCII 範囲外なら
コマンドを送らずに警告を出してください。

## 6. 実機で確認すること

1. `[Hello UIAPduino] とタイプする` がメモ帳に入力される
2. **29 文字を超える文字列**が、途切れず・重複せず・順番どおりに入る（境界の 29 / 30 / 31 文字を試す）
3. `[Enter▼] キーを押して離す` で改行される。矢印・Backspace・Delete も効く
4. `[Ctrl▼] を押しながら [c] キーを押す` でコピーができる（`[Ctrl] + v` で貼れる）
5. **ショートカットの後、修飾キーが残っていない**（続けて文字をタイプして化けないこと）
6. 日本語や記号を渡したときに、無言で化けず警告が出る
7. 停止ボタンでキーが解放される（`PANIC`）

**2 と 5 が要点です。** 2 は上記の「29 文字」の罠、5 は設計方針そのものの検証です。

## 7. 引き継ぎメモ（同じ失敗を繰り返さないために）

### ビルドについて

- **ビルドは指示されたときだけ実行すること。** 勝手に走らせると、利用者が検証のために
  起動している `Scratch UIAPduino.exe` とぶつかり、`app.asar` のロックで失敗します。
  この作業中に 3 回やらかしました
- ビルド前に `win-ia32-unpacked` を削除し、削除できたことを確認してから進めること

### 検証について

- **ブロック定義は、本物の `Runtime` に `_registerExtensionPrimitives()` で登録させて
  確認できます。** `getInfo()` を眺めるだけでは scratch-blocks 用 JSON の生成漏れに
  気づけません（囲みブロックの `SUBSTACK` など）
- **`processor.request` を差し替えれば、デバイス無しでコマンド列を検証できます。**
  マウスの囲みブロックはこの方法で 15 項目を確認しました
- **実機の検証は、実際の使い方で行うこと。** 「Scratch の上で試す」と、
  Scratch 自身が入力を受け取るだけの状況になり、何も一般化できません。
  この取り違えで一度、誤った結論に至りました

### やってはいけないこと

- **PowerShell で `user32` を叩く実装を作らないこと。** Avast が
  `IDP.HELU.PSE85`（コマンドライン検出）でブロックします。詳細は README
- **仮想キーを端から端まで走査しないこと。** 日本語 IME の環境では VK `0xF4` が
  常に「押されている」と報告されます

### 既存の制約

- eslint は既存コードの時点で通っていません（`no-console` と、`'ja-Hira'` を含む
  メッセージ表の `quote-props`）。**新種の違反を増やさなければ十分**です
- `Scratch-UIAPduino-*-sketch.zip` は**どのビルドスクリプトも生成していません。**
  手作業のものが残るため、`.ino` を変えたら取り残されます
